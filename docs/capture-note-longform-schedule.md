# 记录体裁：便签、长文与「安排」

发送框只有一个，但产出两种体裁，日期的含义统一成「提醒」。这份文档记下取舍，后来的改动先读它。

## 便签（默认）

时间线顶上的发送框就是便签。便签是短想法，格式刻意收窄：

| 露出 | 不露出（交给长文） |
| --- | --- |
| 正文、加粗、无序/有序列表、待办、`#标签`、`[[双链`、图片 | 标题、斜体、引用、代码块、表格 |

- 工具栏：标签、图片 ｜ 加粗、列表、有序列表、待办 ｜ 安排、语音 ｜ 写长文。
- 选中文字的浮动菜单在便签里只有加粗、删除线、链接（`FormatBubbleMenu variant="note"`）。
- Markdown 快捷输入（`## `、`> `、三个反引号）仍然识别。这是有意的：老内容、Memos 客户端写入的内容和熟手的输入不能因为收窄按钮而坏掉。收窄的是入口，存储格式仍是 GFM。
- 图片最多 9 张（`MAX_MEMO_IMAGES`），超出时在选择阶段就丢弃并提示「写成长文」。卡片里一张图按原比例显示，2 张或 4 张排两列，其他数量排三列正方形。

## 长文

「写长文」打开全屏画布，默认体裁是文章，完整 Markdown 工具都在。画布右上角仍可切回便签发送，给只想要大空间的人。

## 安排：日期 = 提醒

原先「插入日期」只是往正文里插 `2026-10-30 ` 这段字，没有任何语义。现在换成「安排为待办」：

- 选哪天提醒（今天 / 明天 / 下周一 / 自选日期），可选放进哪个项目，两者都可以单独设。
- 发送时，便签里每条未勾选的待办成为一项任务（`due_at` = 选定日期，`source_memo_id` = 这条便签）；没有待办行时，整条便签的首行成为一项任务。
- 发送框底部显示安排标签：日期 · 项目 · 将建几项待办。
- 离线发送时安排随队列保存，联网后补建；补建前按 `source_memo_id` 查已建标题，重放不会重复建任务。

### 两边勾选同步（服务端）

便签里的待办行和由它建出的任务是同一件事，勾哪边都同步另一边。匹配键是任务的 `source_memo_id` 加标题（标题等于那一行的文字），便签里不藏任何 id。

- 改便签内容时（`updateMemo`）：对比前后待办行，勾上的把对应任务置为完成，取消勾的把已完成任务重开为待办；进行中的任务不被取消勾打回。
- 改任务状态时（`updateTask`）：进入或离开「完成」时，回写源便签里同名那一行。
- 回写时的 WHERE 只命中状态不同的任务，所以两个方向不会互相反弹。同步是尽力而为：便签被删、进回收站或那一行被改名后，同步自然停止，主操作照常成功。

### 提醒

每日 cron（UTC 03:17）在原有「逾期」之外新增「今日到期」：每项当天到期的未完成任务写一条 `task_due` 通知，并给每位用户发一条聚合 Web Push。Memos 兼容的 Connect 通知列表不返回 `task_overdue` / `task_due` 这类 FlareMo 专属类型。

## 刻意不做的事

- 不做精确到时刻的闹钟、重复提醒、子任务。提醒只到「天」，跟着每日回顾一起送达；更细的需求交给专门的待办软件。
- 不让标签自动映射项目。标签用来整理想法，项目用来推进工作，两者用「安排」连接，不混成一个概念。
- 便签不做标题层级和排版。想排版就是在写文章，入口在「写长文」。
